## Qué es

Motor **Google Sheets → Apps Script → Google Slides** que genera presentaciones
configurables sin tocar código. Diseño **por registros**: agregar una base o plantilla =
agregar una fila, no código.

**Regla de oro:** toda la aritmética vive solo en `Marcadores.gs`. El resto lee config,
lee datos o pinta Slides.

**Framing institucional:** *el sistema arma el informe; las conclusiones las sigue
escribiendo el equipo.*

## Aprendizajes de esta sesión

**Convención de `campo_logico`.** En `MARCADORES` el prefijo de familia vive en
`marcador`, **no** en `campo_logico`: `marcador='ecv_inscriptos'`, `familia='ecv'`,
`campo_logico='inscriptos'`. El `MAPEO_completo.md` lo escribió con prefijo porque venía
de la vista de tokens — al sembrar va **sin** prefijo.

**`upsertPorClave_` es destructivo.** Arma la fila con
`headers.map(h => (h in obj) ? obj[h] : '')`, o sea que **escribe vacío cualquier
columna que el objeto semilla no traiga**. Al agregar columnas nuevas hay que actualizar
también los arrays `SEED_*`, y al resembrar `MARCADORES` hay que usar una variante que
solo complete celdas vacías (ver Paso 2.5).

**Operaciones genéricas, no función por marcador.** El `Paso-3.md` original pedía una
función por token (~200). El contrato del stub ya decía operaciones genéricas
(`SUMA/CONTEO/RATIO/ULTIMO/TEXTO`); manda el contrato, si no cada informe nuevo vuelve a
requerir código.

**Método recomendado para el Paso 3: corte vertical.** No cablear los 200 marcadores;
elegir una slide (sugerido: JM slide 5, una sola base, mezcla SUMA y PCT) y llegar de
punta a punta hasta el Slides generado. Si el diseño falla, aparece igual con 5 tokens
que con 200 — y mucho más barato.

**⚠ El episodio de Drive.** "Registrar plantillas" veía la carpeta vacía pese a permisos
correctos y Slides nativos. Se descartaron `.pptx`, accesos directos, subcarpetas,
scopes y autorización vieja. **La causa real: Google marcó las dos plantillas como
spam.** Un archivo en spam sigue existiendo y compartido, pero no aparece en
`getFiles()`. Probable disparador: dos cuentas Gmail nuevas, sin historial entre sí,
compartiéndose archivos pesados — patrón típico de spam para el clasificador. **Si algo
en Drive "no aparece" pese a permisos correctos, revisar spam antes que el código.**
Mitigación: marcar "No es spam", agregarse a contactos mutuamente; a futuro, un Shared
Drive evita el problema de raíz (requiere Workspace).

## Método de trabajo

- **Un paso = un prompt para Code = una prueba del usuario = un commit.** No se avanza
  hasta que el paso actual pasa.
- Code documenta en `HANDOFF.md` y commitea **recién después** de que el usuario confirma.
- **Ubicación de archivos:** prompts → `docs/Prompts/Paso-*.md` · doc maestro →
  `Plan Inicial/PROYECTO.md` · operación → `docs/RUNBOOK.md` · superados →
  `Plan Inicial/_archivo/`.
- Todo lo que se conversa se entrega **como archivo para el repo**, no suelto en el chat.
